## 验证边界和后续处置

- 本机 Docker 未启动，本轮没有将结构脚本导入独立 MySQL 实例；结构和脱敏检查属于静态验证。
- Gitleaks 未安装；本轮检查了当前跟踪文件和历史 SQL 的数据语句、邮箱、手机号格式。DATA-01 仍需补做专用密钥扫描；扫描发现的默认凭据再按 DATA-02/03 逐项处理。
- 强制更新只清理目标分支的可达历史。旧克隆、备份、分叉仓库、代码托管平台缓存以及已下载副本可能继续保留原数据。本机原工作区的 `.git` 仍是旧历史，应在保全未提交改动后改用干净克隆，并安全清除旧副本；协作者也需重新克隆。
- 应检查并限制已有生产备份的访问范围，按数据泄露事件评估通知和密钥、密码轮换。仅清理 Git 历史不能撤回已经暴露的信息。
