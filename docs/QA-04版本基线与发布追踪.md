## 本地工作区快照

在仓库根目录运行：

```powershell
python scripts/qa04_snapshot_worktree.py
```

快照保存在 E 盘仓库的 `backup/qa04-local-<UTC时间>/`，包含以当前 HEAD 为基准的变更文件归档、每个文件的 SHA-256、删除记录、排除记录、待生产核对的相对路径清单和归档校验和。`backup/` 已从 Git 与 Docker 构建上下文排除。个人配置、私有密钥、生成文件不进入归档；这些文件如需备份，必须走受控私有备份渠道。快照生成后继续修改文件，应重新生成快照，不能沿用旧哈希。

快照是本地源码证据，**不能替代** VM 源码及数据库、MinIO、配置备份。此前的生产备份仍需确认可用性和当前时间点。

## 生产只读取证与三方比对

在不停止现有容器的前提下，把 `scripts/qa04_collect_production.sh` 和本地快照中的 `paths.txt` 复制到 VM。先核对脚本内容，再在 VM 上运行：

```bash
bash qa04_collect_production.sh /opt/software-group /opt/software-group/qa04-paths.txt
```

脚本只读取 Compose 容器及镜像元数据、当前源码和部署配置哈希、Flyway 历史；不输出 `.env` 内容、数据库密码或业务数据。输出在 VM 的 `backup/qa04-production-<UTC时间>/`。其中 `git-head.txt` 与 `git-status.txt` 判断 VM 目录是不是干净的 Git 工作区；`containers.tsv`、`images.tsv` 记录实际运行镜像 ID 及可用的 registry digest；`flyway-history.tsv` 记录数据库迁移版本。若查不到 Flyway 历史，查看 `flyway-query-error.txt` 并人工核查数据库，不能默认视为已迁移。

把取证目录复制到受控本地目录后，运行：

```powershell
python scripts/qa04_compare_production.py backup/qa04-local-<UTC时间>/manifest.json backup/qa04-production-<UTC时间>/source-sha256.txt
```

该比对检查**本地未提交的变更文件**与 VM 同路径文件是否一致。基础版本比较还需核对本地 HEAD、GitHub SHA 与 VM `git-head.txt`；如果 VM 没有 Git 元数据，需用镜像构建记录或原始制品确定来源，不能凭文件名或容器创建时间推断提交号。若某些容器没有 registry digest，保留镜像 ID 和镜像归档/校验和，并在发布记录中说明。

## 形成可复现发布

1. 本地修复已按 QA-01、QA-03、镜像构建、4.7 运维配置、部署文档和 QA-04 工具分组提交；每组暂存后检查文件范围及 `git diff --cached --check`。`.claude/settings.local.json` 已停止跟踪且仍保留在本机；生成目录和备份目录由 Git 忽略。无关知识整理文档与旧诊断脚本仍未跟踪，不进入发布候选。
2. 发布前从 `Version-2` 的**干净提交**构建。运行 `bash scripts/qa04_preflight_release.sh`，失败时停止发布。通过后执行 `export SOURCE_COMMIT="$(git rev-parse HEAD)"`，再运行 `docker compose build`。九个应用镜像会写入 `org.opencontainers.image.revision` 标签；省略该变量时标签是明确的 `unrecorded`，不得按已确认来源发布。CI 冒烟也从 checkout 的 HEAD 注入该标签。当前工作区预期不通过此门禁。
3. 在发布记录中填写：发布时 UTC 时间、Git commit SHA、CI 运行链接及结论、各服务镜像 ID、镜像源码标签和可用 digest、Compose/Nginx 配置 SHA-256、Flyway 版本、备份位置与校验和、验收结果、回滚镜像标签。记录与发布制品一并归档，不能仅记录 `latest`。
4. 只在生产运行镜像的源码提交号有可靠证据时，为**该提交**建立 `production-<日期>` Git tag。若旧镜像没有源码标签或构建记录，先保持“生产来源待确认”，不要把当前本地 HEAD 当成生产标签。
5. 后续发布从干净提交构建或取用已验证镜像，并按镜像 ID/digest 核对部署结果。复制整个工作目录只能用于传输已核对的制品，不能作为唯一发布方法。
