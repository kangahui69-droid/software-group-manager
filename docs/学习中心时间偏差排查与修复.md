# 学习中心时间偏差排查与修复

## 已确认的代码问题

旧逻辑由 Java/JDBC 写入 `study_session.check_in_time`，再由数据库 `NOW()` 计算结束时间与分钟数；用户页还把无时区的 `yyyy-MM-dd HH:mm:ss` 交给浏览器 `Date` 解析。部署环境的时间解释不一致时，会出现开始后立刻显示约 8 小时、结束后出现负分钟数。结束接口此前返回的是“今日累计”，多个错误记录会叠加。

现在开始、结束与计时基准都使用数据库会话时钟；连接初始化为北京时间。用户页计时器使用数据库返回的已学习秒数，按浏览器单调时钟递增。结束接口分别返回本次 `duration` 与今日累计 `todayDuration`。用户和管理端读取历史负时长时，仅在数据库的 `created_at` 与 `check_out_time` 能推算出 0–960 分钟的合理区间内展示推算值；无法推算的记录显示“待校正”。数据库原值不会因页面读取而改变。

## 生产环境只读核查

发布前在业务数据库执行以下查询，保存结果并核对时区和受影响行。不要先修改数据。

```sql
SELECT @@session.time_zone AS session_zone, @@global.time_zone AS global_zone,
       NOW() AS database_now, UTC_TIMESTAMP() AS utc_now;

SELECT id, user_id, session_date, status, check_in_time, created_at,
       check_out_time, duration,
       TIMESTAMPDIFF(MINUTE, created_at, check_in_time) AS start_offset_minutes,
       TIMESTAMPDIFF(MINUTE, created_at, check_out_time) AS inferred_duration_minutes
FROM study_session
WHERE duration < 0
   OR ABS(TIMESTAMPDIFF(MINUTE, created_at, check_in_time)) >= 60
ORDER BY id DESC
LIMIT 100;
```

如果结果中的 `created_at` 与 `check_out_time` 也不可信，应依据业务日志和备份逐条核对，不能按推算值批量改写。对于可核实的记录，先备份，再在事务中按 ID 定向修正 `check_in_time` 与 `duration`。本次代码不自动改写历史数据。

## 验收

使用用户端开始学习，确认计时从约 0 秒增长；结束后本次分钟数非负，今日累计与记录列表一致。管理端“学习管理”应显示相同的开始、结束时间和时长。重复测试退出登录自动结束和 22:00 自动结束。生产发布与历史数据校正需要单独执行。
