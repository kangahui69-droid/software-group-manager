# MIG-02 内容服务 DAO 修复验证报告

日期：2026-11-15。范围：`content-service` 本地代码；未操作生产 VM。

## 问题复核

修复前，新闻、活动群组、群成员、群消息、用户群组关系、成员资料、文件和用户共 8 个 DAO 存在固定空列表、`null`、`true` 或 `1` 的占位返回。部分读接口恒为空，部分写接口可能报告成功而没有数据库变更。群组服务还有更新只改内存对象、删除消息按群组 ID 查询等调用链错误。仓库 Nginx 配置已有内容服务 API 路由，因此问题成立。

## 本次修复

- 8 个 DAO 按现有 MySQL 表结构实现查询、写入、更新和删除；新增记录使用数据库自增 ID，更新与删除依据真实影响行数返回结果。
- 群组更新写库；消息删除按消息 ID 查询后核对发送者；群组创建、加人、移人和删除采用事务，后续写入异常时回滚。
- 新闻创建必须提供已存储正文的 `contentPath`；直接传入 `content` 正文会返回 400，避免正文被静默丢弃。标题与群组名等长度约束对齐现有表结构。
- 群组禁言截止时间以 `TIMESTAMP` 写入数据库，保留时分秒。

## 验证结果

在本机临时 MySQL 8 的 `mig02_test` 库中导入仓库的无业务数据结构基线，共 45 张表。集成测试在清理数据前强制校验数据库名为 `mig02_test`，只使用虚构用户。

执行 `mvn -o -pl content-service -am test -q`：**内容服务 175 项、公共模块 15 项，共 190 项通过，0 失败、0 错误、0 跳过**。其中 3 项真实 MySQL 集成测试验证新闻状态和读写、群组成员与消息权限、群组禁言时间精度，以及群组创建失败时的事务回滚。执行 `mvn -o -pl content-service -am -DskipTests package -q` 返回 0，生成服务 JAR。

## 生产切流前的限制

1. 旧 WAR 新闻表单提交富文本正文并由 WAR 写入 HTML 文件；当前微服务只持久化 `contentPath`，尚未实现对应的正文上传、存储和文件存在性校验。旧页面不能直接切到新接口。
2. 现有 `muteMember` 名称和目标用户参数来自旧调用链，但实际更新 `activity_group.is_muted`，禁言整个群组。若产品要求只禁言单个成员，需要设计独立接口并使用 `group_member.muted` 字段，完成权限和页面联调后才可切流。
3. 旧 WAR 与微服务的 HTTP 方法、页面/JSON 响应和分页行为仍需逐项对照。生产数据和生产容器未用于测试；新闻、群组路由应分别验收和切换。

结论：**MIG-02 的 DAO 占位实现已在本地代码中消除；内容服务迁移尚未完成生产验收。** 本次没有修改生产 Nginx、容器或远端 Git 分支。
