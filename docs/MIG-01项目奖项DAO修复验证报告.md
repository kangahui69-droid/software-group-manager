# MIG-01 项目与奖项 DAO 修复验证报告

日期：2026-11-14。范围：`project-award-service` 本地代码；未部署到生产 VM。

## 复核结论

修复前，`ProjectDAO`、`AwardDAO`、`AwardImageDAO`、`DictionaryDAO`、`FileStorageDAO` 和 `UserDAO` 存在固定返回空列表、`null`、`true` 或 `false` 的占位方法。部分读接口因此恒为空，部分写接口可能报告成功但不改数据库。项目创建还会被占位的用户查询阻断，因此不能笼统地说所有写接口都会虚假成功。仓库的 Nginx 配置把 `/api/projects` 和 `/api/awards` 指向该服务，风险成立。

## 本次代码修复

- 六个 DAO 改用 Spring JDBC 访问现有 MySQL 表；查询过滤软删除记录，写入读取真实自增 ID，更新、审核和删除按状态与影响行数判定结果。
- 项目创建写入项目、负责人关系和历史记录；成员申请、审核、计划、进度均落库。项目创建与成员审核使用事务，异常时回滚。
- 奖项提交写入奖项、成员和图片关系；奖项提交使用事务。奖项图片、字典、文件、用户查询按现有字段映射。
- 项目名、分类、计划日期和奖项名称、日期的校验与数据库字段约束对齐，避免合法性检查通过后由数据库报错。

## 测试与结果

使用仓库的结构基线 `sql/software_group.sql` 建立本机隔离的 MySQL 8 数据库 `mig01_test`。测试只在 `MIG01_MYSQL_URL` 非空时运行，测试代码还校验连接的数据库名必须等于 `mig01_test`，以防误清理其他库。库中仅插入虚构测试用户和数据。

命令：`mvn -o -pl project-award-service -am test -q`，连接上述临时数据库。结果：**服务模块 168 项、公共依赖模块 15 项，共 183 项通过，0 失败，0 错误，0 跳过**；其中 3 项真实 MySQL 集成测试分别覆盖项目流程、奖项和辅助 DAO 流程、项目创建失败时的事务回滚。`mvn -o -pl project-award-service -am -DskipTests package -q` 返回 0，生成服务 JAR。未使用生产数据、生产容器或生产数据库。
