## 三、重构优化（两个模块统一）

### Route enum 模式

将路径匹配从 if-else 链转为枚举查表，扩展性更好。

### Path Matcher 方法提取

| 模块 | 方法 |
|------|------|
| Group | `isGroupDetailPath`, `isGroupMessagesPath` 等 |
| Attendance | `isStatsPath`, `isMyPath`, `isMakeupListPath` 等 |

### GET/POST 分离

- `dispatchGetRequest()` / `dispatchPostRequest()` - 集中路由分发
- `handleXxx()` - 独立处理器方法

## 四、关键问题发现与解决

| 问题 | 原因 | 解决 |
|------|------|------|
| `jakarta.servlet` vs `javax.servlet` 编译错误 | IDEA/环境差异 | 统一使用 `javax.servlet.*` |
| `HttpServlet.doPatch` 方法不存在 | PATCH在HttpServlet中未定义 | 移除PATCH相关测试 |
| 路径匹配多个route冲突 | 正则 `/\d+` 和 `/\d+/messages` 冲突 | Route enum中按优先级匹配 |
| `AttendanceService` 无无参构造函数 | Service需要DAO依赖注入 | 添加无参构造函数，内部实例化DAO |
| 测试 mock `getPathInfo()` 返回null | 测试只 mock 了 `getRequestURI()` | 使用 `Answer` 自动从 URI 提取 |
| POST 请求体解析返回null | `BufferedReader.readLine()` 只读一次 | 添加 `setupJsonBody()` 辅助方法 |

## 七、经验总结

1. **Route enum 模式**：路径匹配从 if-else 链转为枚举查表，扩展性更好
2. **TDD开发流程**：先写测试明确接口契约，再实现，测试即文档
3. **无参构造函数模式**：Service层同时支持无参构造（Servlet使用）和带DAO参数构造（测试使用）
4. **测试路由技巧**：使用 `Answer` 从 `getRequestURI()` 自动推断 `getPathInfo()`
5. **POST body mock**：添加 `setupJsonBody()` 辅助方法简化 JSON 请求体 mock
6. **最小实现原则**：严格按照测试覆盖范围实现，不添加未测试的功能
