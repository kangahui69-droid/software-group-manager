### 4. 重构优化

**AttendanceApiServlet 重构**（Green → Refactor）

重构前问题：
- `doGet`/`doPost` 方法过长
- 路径判断使用 if-else 链
- ID提取逻辑重复

重构后：
- **Route enum 模式**：消除 if-else 链，路径匹配转为表驱动
- **Path Matcher 方法提取**：
  - `isStatsPath()` / `isMyPath()` / `isMakeupListPath()`
  - `isCheckInPath()` / `isCheckOutPath()` / `isApprovePath()` 等
- **GET/POST 分离**：
  - `dispatchGetRequest()` - 集中 GET 路由分发
  - `dispatchPostRequest()` - 集中 POST 路由分发
- **独立处理器方法**：`handleListAttendance()` / `handleCheckIn()` 等
- **Response Helper 提取**：`sendNotFound()` 替代 `sendError(resp, 404, ...)`

## 二、关键问题发现与解决

| 问题 | 原因 | 解决 |
|------|------|------|
| `AttendanceService` 无无参构造函数 | Service需要DAO依赖注入 | 添加无参构造函数，内部实例化DAO |
| 测试 mock `getPathInfo()` 返回null | 测试只 mock 了 `getRequestURI()` | 使用 `Answer` 自动从 URI 提取 pathInfo |
| POST 请求体解析返回null | `BufferedReader.readLine()` 只读一次 | 添加 `setupJsonBody()` 辅助方法 mock |
| 无效ID格式应返回400而非404 | 路由匹配未处理非数字ID | 添加 `isApprovePath`/`isRejectPath` 检测非数字格式 |

## 五、经验总结

1. **无参构造函数模式**：Service层需要同时支持无参构造（Servlet使用）和带DAO参数构造（测试使用）
2. **测试路由技巧**：使用 `Answer` 从 `getRequestURI()` 自动推断 `getPathInfo()`，避免每个测试单独 mock
3. **POST body mock**：添加 `setupJsonBody()` 辅助方法简化 JSON 请求体 mock
4. **Route enum 模式一致性**：所有 API Servlet 采用统一的 Route enum 模式，代码风格一致
5. **最小实现原则**：严格按照测试覆盖范围实现，不添加未测试的功能
